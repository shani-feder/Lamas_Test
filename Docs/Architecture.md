# מסמך ארכיטקטורה - מערכת בקרות נתונים דינאמית

## סקירה כללית

המערכת מאפשרת למשתמשים עסקיים להגדיר ולהריץ בקרות על נתונים ללא צורך בידע טכני או כתיבת SQL.

## רכיבים עיקריים

### 1. Frontend (Angular 17)

| רכיב | תפקיד |
|------|-------|
| ControlListComponent | הצגת רשימת בקרות, הרצה ומחיקה |
| ControlEditorComponent | יצירה ועריכה של בקרות |
| ControlResultsComponent | הצגת תוצאות הרצה וחריגות |
| ApiService | תקשורת עם ה-Backend |

### 2. Backend (.NET 8)

| שירות | תפקיד |
|-------|-------|
| MetadataService | ניהול מטא-דאטה (ישויות, שדות, קשרים) |
| ControlService | CRUD לבקרות |
| SqlGeneratorService | תרגום הגדרת בקרה ל-SQL דינאמי |
| ControlExecutionService | הרצת בקרות ושמירת תוצאות |

### 3. Python Service

| Endpoint | תפקיד |
|----------|-------|
| /api/ai/analyze | ניתוח מבנה DB והצעת בקרות |
| /api/ai/suggestions/{id} | הצעות לישות ספציפית |

### 4. Database (SQL Server)

**טבלאות נתונים:**
- Employees, Departments, Projects, EmployeeProjects

**טבלאות מטא-דאטה:**
- BusinessEntities - מיפוי טבלאות לשמות עסקיים
- BusinessFields - מיפוי עמודות לשמות עסקיים
- EntityRelations - קשרים בין ישויות

**טבלאות בקרות:**
- Controls - הגדרות בקרות
- ControlConditions - תנאי בקרה
- ControlJoins - קשרים נדרשים לבקרה
- ControlExecutions - היסטוריית הרצות

## מנגנון הבקרות

### תהליך הגדרת בקרה:
1. משתמש בוחר ישות ראשית (בשם עסקי)
2. מוסיף קשרים לישויות נוספות (אופציונלי)
3. מגדיר תנאים על שדות (בשמות עסקיים)
4. שומר את הבקרה

### תהליך הרצת בקרה:
1. SqlGeneratorService מתרגם את ההגדרה ל-SQL
2. ControlExecutionService מריץ את השאילתה
3. התוצאות נשמרות ב-ControlExecutions
4. הרשומות החריגות מוצגות למשתמש

### יצירת SQL דינאמי:

## אבטחה

1. **SQL Injection Prevention:**
   - שימוש בפרמטרים מוגדרים מראש
   - Whitelist של אופרטורים
   - Escape לערכים

2. **Read-Only:**
   - רק שאילתות SELECT
   - אין אפשרות לשנות נתונים

3. **Validation:**
   - בדיקת קיום שדות וישויות
   - בדיקת תקינות אופרטורים

## הרחבות אפשריות

1. **תזמון בקרות** - הרצה אוטומטית בזמנים קבועים
2. **התראות** - שליחת מייל כשנמצאות חריגות
3. **ייצוא** - ייצוא תוצאות ל-Excel/CSV
4. **דשבורד** - סיכום מצב כל הבקרות
5. **היסטוריה** - השוואת תוצאות לאורך זמן
6. **הרשאות** - ניהול משתמשים והרשאות

## הנחות עבודה

1. המשתמשים מכירים את המונחים העסקיים
2. מבנה הטבלאות יציב יחסית
3. כמות הנתונים סבירה (עד מיליוני רשומות)
4. SQL Server זמין ומוגדר

## מגבלות

1. אין תמיכה ב-Subqueries מורכבים
2. אין תמיכה ב-Aggregations (GROUP BY)
3. אין תמיכה ב-UNION
4. מוגבל לקשרים שהוגדרו במטא-דאטה
